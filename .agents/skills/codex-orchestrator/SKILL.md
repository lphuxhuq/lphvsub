# Codex Orchestrator

Codex is the controller: architect, planner, reviewer, and final decision-maker. Antigravity is the implementation worker. Computer Use is the UI automation path for controlling Antigravity and for real UI/UX verification when available.

## Resume first

At the start of a run, read `AGENTS.md`, `.codex/state/project-state.md`, `.codex/state/current-task.md`, `.codex/state/progress.md`, the latest test/review result, and the latest handoff/computer-use evidence. Continue from the recorded phase; do not restart blindly.

## Lifecycle

1. **Inspect** - map repository structure, language/framework, build and test commands, entry points, CI, existing agent instructions, Git changes, Antigravity access, Computer Use capability, and UI launch path. Record observed facts and unknowns.
2. **Analyze** - trace the relevant execution flow, identify files and dependencies, separate observed root cause from hypotheses, and document risks. No implementation or delegation during this stage.
3. **Plan** - write `.codex/plans/master-plan.md` using `templates/master-plan.md`; state what will and will not change, dependency ordering, rollback, tests, UI checks, handoff, and evidence.
4. **Decompose** - create one `.codex/tasks/TASK-###.md` per independently verifiable unit using `templates/task.md`. Allowed states: `PLANNED`, `READY`, `IN_PROGRESS`, `VERIFYING`, `REVIEWING`, `BLOCKED`, `FAILED`, `DONE`, `CANCELLED`.
5. **Delegate** - for a READY implementation task, use `.agents/commands/delegate.md` to produce the complete handoff. If Computer Use is available, invoke `computer-use-qa`, use its accessibility → screenshot-coordinate input ladder, verify a visible task marker before sending, confirm acknowledgement by task ID, and save raw text/screenshot evidence. If the Agent input is not addressable, record `HANDOFF_INPUT_UNAVAILABLE`; if Computer Use itself is unavailable, record `COMPUTER_USE_UNAVAILABLE`. Never imply that Antigravity ran without acknowledgement evidence.
6. **Implement** - Antigravity changes only the assigned scope and returns the required report. Codex does not accept a completion claim without comparing the report to the working-tree diff.
7. **Verify** - run the smallest relevant syntax/type/unit/integration/build/runtime checks, then broader regression checks as appropriate. Save output in `.codex/state/test-results.md` and `.codex/evidence/`.
8. **UI/UX verify** - when applicable and Computer Use is available, use `.agents/skills/computer-use-qa/SKILL.md` to exercise the real workflow, states, errors, focus/keyboard/responsive behavior, and capture evidence. Otherwise record `COMPUTER_USE_UNAVAILABLE` or `NOT_APPLICABLE` explicitly.
9. **Review** - apply `.agents/commands/review.md`; decide exactly `PASS` or `FAIL`. On FAIL, create a `FIX-###` task from exact evidence and repeat the loop. Computer Use and UI claims are separate review checks.
10. **Advance/complete** - only a reviewed task with evidence becomes `DONE`; load the next `READY` task. When all tasks are done, run final regression, final UI checks where applicable, final review, and update all state files before declaring `COMPLETE`.

## Prompt provenance (mandatory)

Every prompt sent to Antigravity must be generated by Codex from the current approved plan and one concrete task file. The provenance chain is:

`USER REQUEST -> ANALYSIS -> .codex/plans/master-plan.md -> .codex/tasks/TASK-###.md (READY) -> .codex/evidence/handoff-TASK-###.md -> Antigravity prompt`

Before sending, Codex must verify that the task is `READY`, dependencies are complete, the handoff contains the task's objective/constraints/acceptance criteria/tests, and the prompt hash or timestamp is recorded. Do not send ad-hoc prompts, raw user text, a worker suggestion, or a task that is only `PLANNED`. A handshake/test prompt is allowed only as infrastructure testing and must never be treated as implementation work.

After sending, record the exact prompt and source paths in the handoff evidence. Parse Antigravity responses for explicit task markers, but treat them as progress evidence; Codex retains authority over status, scope, and completion.

Use `.agents/commands/prepare-handoff.md` and `scripts/render_handoff.py` to render a deterministic, SHA-256-bound handoff. The renderer must reject a task that is not `READY`. If the plan or task changes, regenerate the handoff and hash before sending.

## Worker-unavailable fallback

If Antigravity or Computer Use cannot be reached, do not fabricate a handoff, acknowledgement, or UI result. Record `COMPUTER_USE_UNAVAILABLE` (and the exact Antigravity blocker), then either wait/request the missing capability or implement a separately labelled Codex-owned task only after the user explicitly authorizes that fallback. Codex-owned implementation evidence must never be presented as Antigravity evidence.

## Command mapping

Natural language maps to the repository commands: analyze -> `analyze.md`, plan -> `plan.md`, send/implement -> `delegate.md` + `execute.md`, verify/check UI -> `verify.md`, review -> `review.md`, fix -> `fix.md`, status -> `status.md`, finish -> `complete.md`. "Open Antigravity" and "Send TASK-### to Antigravity" require actual Computer Use when available.

## Evidence and state invariants

- Every meaningful implementation has an ID and a task file.
- Evidence labels what it proves: implementation, automated tests, Antigravity control, UI/UX, or Codex review.
- `DONE`, `PASS`, and `COMPLETE` require evidence; otherwise use `VERIFYING`, `FAILED`, `BLOCKED`, or `IMPLEMENTED - VERIFICATION PENDING`.
- Update `.codex/state/project-state.md`, `current-task.md`, and `progress.md` after each meaningful stage. Record blockers rather than hiding them.
- If a worker reports a blocker, validate it, mark the task `BLOCKED`, and decide whether to clarify, reassign, or request user input.
- Recognize progress only from fresh Agent captures. Parse explicit `TASK ID`, `STATUS`, `PROGRESS`, `FILES CHANGED`, `TEST RESULTS`, `BLOCKERS`, and `NEXT ACTION` markers; store raw text and normalized state, and treat worker suggestions as non-authoritative.
- Reconcile Agent markers against the task file and `git diff`; mark `STATE_CONFLICT` for discrepancies and resolve them before advancing. On resume, detect stale handoffs/state by comparing timestamps and prompt hashes.
- If tests fail or UI verification fails, perform root-cause analysis and create a fix task; never ask for a blind patch.

## Scope and safety

Preserve existing instructions and user modifications. Do not modify orchestration state files from Antigravity unless explicitly assigned. Do not approve destructive actions through Computer Use without explicit authorization. Do not create commits unless requested.
